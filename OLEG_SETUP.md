# Олеже, з чого почати

**Версія 1.1** · оновлено 18.09.2026 — усі дані тепер зберігаються на
сервері в базі, а не в браузері. Це додало один крок (9½) з рішенням,
яке треба ухвалити вам.

Це покрокова інструкція. Технічних знань не потрібно — усе робиться
через сайти й кнопки. Разом це **близько двох годин**, можна розбити на
два вечори.

**Головне правило:** усі акаунти реєструєте **ви, на свою пошту**.
Друг потім отримає доступ як співробітник. Це не про довіру — це про те,
щоб продукт не завис, якщо хтось із вас поїде чи захворіє.

## Крок 1. GitHub — місце, де живе код

**Навіщо:** це «Google Drive для програмного коду». Там зберігається кожна
версія застосунку, і звідти код автоматично потрапляє на сервер.

1. Відкрийте **github.com** → **Sign up**
2. Пошта, пароль, ім'я користувача (наприклад `olehkarpyk`)
3. Підтвердіть пошту
4. **Обов'язково увімкніть двофакторну автентифікацію:**
   Settings → Password and authentication → Two-factor authentication →
   через застосунок (Google Authenticator або Authy), не через SMS
5. **Збережіть коди відновлення** в менеджер паролів. Якщо загубите
   телефон і коди — доступ до коду втрачено назавжди
6. Створіть репозиторій: **New repository** → назва `say-it-anyway` →
   **Private** → створити
7. Додайте друга: Settings → Collaborators → Add people

## Крок 2. Домен — адреса застосунку

**Навіщо:** щоб давати людям посилання на кшталт `sayitanyway.app`, а не
набір цифр. Домен потрібен до HTTPS, до аналітики й до встановлення на
телефон.

1. Зайдіть на **namecheap.com** або **porkbun.com**
2. Пошукайте вільне ім'я. Варіанти в порядку переваги:
   - `sayitanyway.app`
   - `sayitanyway.com`
   - `nebiysia.app`
3. Купіть на **1 рік** (≈$12–15). Більше поки не треба
4. **Увімкніть WHOIS Privacy** — інакше ваші ім'я, адреса й телефон
   стануть публічними
5. Увімкніть 2FA в акаунті реєстратора

## Крок 3. Cloudflare — швидкість і захист

**Навіщо:** безкоштовно прискорює сайт, захищає від атак і спрощує
налаштування. Він стане «диспетчером», який направляє відвідувачів на ваш сервер.

1. **cloudflare.com** → Sign up (безкоштовний план)
2. **Add a site** → введіть ваш домен
3. Cloudflare покаже два рядки — це «сервери імен»
4. Поверніться до реєстратора домену → Nameservers → **Custom DNS** →
   вставте ці два рядки
5. Зачекайте від 15 хвилин до кількох годин
6. Увімкніть 2FA

> Далі DNS-записи налаштує друг — від вас нічого не треба.

- [ ] Cloudflare створено
- [ ] Сервери імен замінено в реєстратора
- [ ] 2FA увімкнено

## Крок 4. Hetzner — сервер

**Навіщо:** це комп'ютер у німецькому дата-центрі, який працює цілодобово
й на якому живе застосунок.

1. **hetzner.com/cloud** → Sign up
2. Підтвердження особи: Hetzner може попросити документ або пробний
   платіж. Це нормально, звичайна практика
3. Додайте картку
4. Створіть проєкт: **New Project** → назва `say-it-anyway`
5. **Сервер поки не створюйте** — це зробить друг, йому треба вибрати
   налаштування
6. Увімкніть 2FA
7. Дайте другу доступ: Security → API Tokens → **Generate API token** →
   права **Read & Write** → скопіюйте й передайте другу **захищеним
   каналом** (Signal, менеджер паролів — не звичайним месенджером)

> **Що вибиратиме друг:** тип CX22 (2 ядра, 4 ГБ, ~€5/міс), локація
> Nuremberg або Helsinki, операційна система **Ubuntu 24.04 LTS**.
> Вам це знати не обов'язково, але хай буде.

## Крок 6. Google Analytics — статистика

**Навіщо:** щоб бачити, скільки людей відкрило застосунок, скільки дійшло
до першого уроку і на якому кроці вони зупиняються. Без цього тест на
15 людях дасть відчуття, а не цифри.

1. **analytics.google.com** → увійдіть під своїм Google-акаунтом
2. **Почати вимірювання** → назва акаунта `Say It Anyway`
3. Ресурс: назва `Say It Anyway`, часовий пояс **America/Los_Angeles**,
   валюта USD
4. Категорія — «Освіта», розмір — «Малий»
5. Платформа — **Веб** → URL вашого домену
6. Google покаже **Measurement ID** — рядок виду `G-XXXXXXXXXX`
7. Скопіюйте його й передайте другу. Це **не секрет**, його можна
   надсилати як завгодно

> **Важливо:** друг вставить цей код так, щоб у статистику **ніколи** не
> потрапляв текст відповідей користувачів — тільки знеособлені події
> («відкрив урок», «записав голос»). Так уже влаштовано в поточній
> версії, і так лишиться.

**Друге джерело статистики — власна база.** Тепер увесь прогрес живе на
сервері, тож воронку можна порахувати напряму запитом до бази, без
жодного зовнішнього сервісу. Google Analytics лишається для того, щоб
бачити, звідки люди приходять.

**Що ви побачите через тиждень після запуску:**
Reports → Engagement → Events. Там будуть події `lesson_started`,
`voice_recording_started`, `lesson_completed`. Різниця між першою і
третьою — це і є головна відповідь на питання «чи працює продукт».

- [ ] Google Analytics створено
- [ ] Measurement ID передано другу

**Навіщо:** щоб ви могли відкривати застосунок у себе на комп'ютері й
дивитися зміни одразу, не чекаючи ні на кого.

1. Поставте **Node.js** з **nodejs.org** — версія з позначкою **LTS**
2. Поставте **Git** з **git-scm.com**
3. Поставте **Visual Studio Code** з **code.visualstudio.com**
4. Друг покаже, як забрати код із GitHub
5. У теці проєкту виконайте:
   ```
   npm run dev
   ```
6. Відкрийте **http://localhost:5173**

**Установка бібліотек не потрібна** — у поточній версії залежностей нуль.
Після переходу на React і базу даних додадуться `npm install` і локальна
база, друг покаже.

## Крок 9. Перша справжня перевірка мікрофона

Це найважливіше з усього, що ви зробите цього тижня. Досі застосунок
**жодного разу не тестували на справжньому телефоні** — тільки на
штучному мікрофоні в моєму середовищі.

**На комп'ютері** мікрофон працює одразу на `localhost:5173`.

**На айфоні** — окрема історія. Відкрити `http://192.168.1.x:5173` з
телефона не вийде: мікрофон мовчки не запрацює, бо адреса без HTTPS.
Робочий спосіб — попросити друга запустити:

```
npx cloudflared tunnel --url http://localhost:5173
```

Він дасть адресу на `https://...`, яку можна відкрити з телефона.
Там мікрофон працює.

**Що перевірити:**
- [ ] Safari на айфоні: пройти день 1, записати всі три фрази
- [ ] Прослухати свій запис — чи чутно
- [ ] «Поділитися» → «На екран Home» → відкрити з іконки
- [ ] Заборонити мікрофон у налаштуваннях сайту → чи з'явиться пропозиція
      пройти текстом
- [ ] Закрити й відкрити знову → чи зберігся прогрес
- [ ] Відкрити той самий застосунок у режимі «приватного перегляду» →
      прогресу бути не повинно (це нормально: там інший ідентифікатор)

**Якщо щось не працює — напишіть мені точно, що саме і на якому кроці.**
Safari й запис голосу — найризикованіше місце всього проєкту, і краще
дізнатися про проблему зараз, ніж після міграції на React.

## Крок 9½. Одне рішення, яке за вас ніхто не ухвалить

Тепер усі дані зберігаються на сервері в базі — так вирішив ваш друг, і
це правильно для мобільного застосунку й адмінки. Але з цього випливає
питання, яке я не можу вирішити ні за вас, ні за нього.

**Чи зберігаємо ми текст того, що люди кажуть?**

Люди розповідатимуть туди про страх втратити роботу, про родину, яка
лишилася в Україні, про самотність. Це не «дані користувача» — це
особисті історії.

**Якщо зберігаємо:** з'являється порівняння дня 3 з днем 7, людина бачить
свій шлях, ви бачите, як змінюється мова. Це сильна частина продукту.
Ціна — ви стаєте розпорядником чутливих даних із усіма обов'язками.

**Якщо не зберігаємо:** лишаються тільки цифри — скільки секунд говорив,
які конструкції вжив. Прогрес працює, порівняння дня 3 з днем 7 — ні.

**Моя рекомендація — зберігати, але з чотирма умовами:**
1. Окрема згода саме на зберігання тексту, окремо від згоди на запис голосу
2. Термін зберігання 90 днів, потім автоматичне видалення
3. Відповіді, у яких спрацював кризовий детектор, **не зберігаються взагалі**
4. Кнопка «видалити всі мої дані» стирає все з сервера, не тільки з телефона

Усі чотири вже закладені в технічне завдання. Але саме рішення —
зберігати чи ні — ваше. Напишіть, що вирішили.
