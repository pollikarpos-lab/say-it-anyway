# Say It Anyway — технічне ТЗ

**Версія:** 1.0 · **Дата:** 18 вересня 2026
**Для:** розробника, який піднімає інфраструктуру й веде міграцію

---

## 1. Що є зараз

PWA без залежностей: нативні ES-модулі, власний рендер на `h()`,
hash-роутер, `localStorage`, `MediaRecorder`, `SpeechSynthesis`.
Вручну написані manifest і service worker. Складання — власний скрипт
на 90 рядків. Тести — вбудований ранер Node + власний CDP-клієнт.

**Чому так:** середовище збірки не має доступу ні до npm-реєстру, ні до
CDN — 403 на `registry.npmjs.org`, `unpkg`, `cdnjs`, `jsdelivr`.
`npm install` неможливий фізично. Це тимчасове рішення, архітектура
одразу розділена під міграцію.

```
src/
  content/     уроки 1–5, звірені тексти, маршрут   → переноситься як є
  lib/         safety, audio, storage, analytics    → переноситься як є
  providers/   інтерфейси STT/LLM/TTS               → переноситься як є
  app/         роутер, стан, спільні компоненти     → переписується
  screens/     екрани                               → переписується
  styles.css   система токенів                      → у tailwind.config
```

**47 модульних тестів** — чисті функції, переносяться майже без правок.
**150 наскрізних** — під React переписати на Playwright, але як
**специфікація поведінки** вони лишаються: описують, що саме застосунок
має робити на кожному кроці.

## 3. Сервер

**Hetzner Cloud CX22** (2 vCPU, 4 ГБ, 40 ГБ) — з запасом для Postgres +
трьох контейнерів. Локація Nuremberg або Helsinki.

**Ubuntu 24.04 LTS.** Підтримка до 2029, найбільша база документації,
свіжі пакети. Debian стабільніший але зі старішими пакетами; Alpine дає
економію, непомітну на цьому масштабі.

### Базове налаштування

```bash
# користувач замість root
adduser deploy && usermod -aG sudo deploy
# SSH тільки по ключу
sed -i 's/^#*PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

ufw default deny incoming && ufw allow 22,80,443/tcp && ufw enable
apt install -y fail2ban unattended-upgrades
dpkg-reconfigure --priority=low unattended-upgrades
```

Docker + Compose за офіційною інструкцією.

### Caddy замість nginx + certbot

Caddy сам отримує й оновлює сертифікати Let's Encrypt. Весь конфіг:

```caddy
sayitanyway.app {
    handle /api/* { reverse_proxy api:3000 }
    handle { root * /srv/web; try_files {path} /index.html; file_server }
}
admin.sayitanyway.app { reverse_proxy cms:3001 }
```

### Postgres

У Docker, **порт назовні не відкривати** — тільки у внутрішній мережі
Compose. Пароль у `.env`, який не в репозиторії.

### Бекапи

`pg_dump` щодня о 3:00, вивантаження в **Hetzner Storage Box** (€4/міс),
зберігати 14 днів. Раз на місяць — перевірка відновлення на порожню базу.

> Бекап, який ніхто жодного разу не відновлював, — це не бекап.

## 4. API

Версіонування з першого дня: `/api/v1`. Мобільний застосунок з'явиться
пізніше й не має ламатися від змін вебу.

### POST /api/v1/stt

`multipart/form-data`: `audio` (webm або mp4), `lang`, `day`

```json
{ "text": "This week I'm worried…", "confidence": "high", "durationMs": 14200 }
```

### POST /api/v1/analyze

```json
{ "transcript": "…", "level": "A2-B1", "day": 3,
  "targets": [{ "id": "worried", "en": "I'm worried about…" }] }
```

```json
{ "corrections": [{ "kind": "clarity", "before": "I not know",
                    "after": "I don't know", "why": "Заперечення через don't." }],
  "improved": "…", "usedTargets": ["worried"], "totalFound": 6 }
```

`kind`: `clarity` | `natural` | `grammar`. **Максимум 3** — ріже і сервер, і клієнт.

### POST /api/v1/tts

```json
{ "text": "…", "voice": "en-US" }  →  { "url": "https://…/a.mp3" }
```

### Вимоги до промпта `/analyze`

1. `improved` — **та сама думка користувача**, змінена лише форма.
   Заборонено додавати факти, поради, духовні коментарі.
2. У мовному розборі не згадувати Бога, віру, молитву взагалі.
3. `why` — простою українською, без граматичної термінології, де можна.
4. Сервер **не отримує** біблійного тексту й не має його переписувати.

Незалежно від промпта, клієнт проганяє `improved` через `filterAiOutput()`
і не показує текст, що не пройшов перевірку. Сервер — не остання лінія.

### Запобіжники

| Що | Значення |
|---|---|
| Rate limit | 30 сесій на пристрій на добу |
| Розмір аудіо | ≤ 5 МБ, ≤ 70 с |
| Таймаут | 30 с |
| **Денний бюджет** | ліміт у доларах; перевищення → режим демо, не помилка |
| Аудіо на диску | **ніколи** — тільки в пам'яті, видаляється після транскрипції |
| Логи | без тексту відповідей користувачів |
| CORS | тільки свої домени |

> **Бюджетний стоп — не «на потім».** Без нього один бот за ніч з'їсть
> кількасот доларів. Це найдорожча помилка, якої легко уникнути.

### Кризовий сценарій

`detectCrisis()` працює **на клієнті, до запиту**. При спрацюванні
`/analyze` не викликається взагалі — сервер такого тексту не бачить.
Дублюється на сервері як друга лінія.

## 5. База даних

**Поки що Postgres потрібен лише для Payload.** Прогрес користувача
живе в `localStorage` і цього достатньо для тесту на 15 людях.

Таблиці користувачів — **після** доведеного утримання. Реєстрація перед
першим уроком уб'є воронку саме там, де ми її вимірюємо.

Коли дійде до акаунтів: `users`, `progress`, `saved_phrases`, `sessions`.
Аудіо в базі не зберігається ніколи.

## 6. Payload CMS

**Payload 3 побудований на Next.js** — це окремий застосунок, а не
бібліотека всередині React-фронта. Врахуйте в структурі монорепо:
`apps/cms` — самостійний Next.js, спільна з API база.

Домен `admin.sayitanyway.app`.

**Колекції:**

| Колекція | Поля |
|---|---|
| `passages` | `refUk`, `refEn`, `uk[]`, `en[]`, `translation`, **`verifiedAgainst[]`**, `contextBody`, `contextCaution` |
| `lessons` | `day`, `kind`, `title`, `intro{christian,open}`, `lifeQuestion`, `targets[]`, `practice{}`, `step{}` |
| `translations` | `code`, `title`, `licence`, `licenceUrl` |

**Жорсткі правила:**
- `verifiedAgainst` — обов'язкове, **мінімум два джерела** для української
- Публікація уривка лише після заповнення джерел звірки
- Поле «контекст» обов'язкове і візуально відділене від тексту Писання
- Ролі: `admin` (Олег), `editor`

`packages/content` лишається джерелом правди для вже написаних днів 1–5;
Payload наповнюється з них міграцією.

## 7. Аналітика

**Події вже визначені** в `src/lib/analytics.js` — 22 штуки, з білим
списком полів. Вільний текст фізично не може туди потрапити: усе, що не
в списку дозволених полів, відкидається.

Ключові для воронки:
`landing_viewed` → `onboarding_completed` → `lesson_started` →
`voice_recording_started` → `voice_submitted` → `lesson_completed`

**GA4 чи Plausible — рішення за вами.** Коротко:

| | GA4 | Plausible / Umami |
|---|---|---|
| Ціна | 0 | 0 (self-host на тому ж VPS) |
| Cookie-банер | **обов'язковий** | не потрібен |
| ЄС | питання передачі даних досі спірне | дані лишаються на вашому сервері |
| Глибина | велика | базова, але для воронки достатньо |

Олег уже реєструє GA4 — він знайомий і безкоштовний. Але для аудиторії з
ЄС **Plausible на тому ж сервері знімає і банер, і юридичне питання**, а
для нашої воронки його можливостей вистачає з запасом. Варто розглянути.

**У будь-якому разі: у події не потрапляє текст відповідей, транскрипції
чи збережені фрази.** Тільки назва події, день, тривалість.

## 9. Перехід із чату в код

Зараз Claude працює в ізольованому середовищі й віддає архіви. Після
Етапу 1 краще працювати інакше — **Claude Code просто в репозиторії**:

**Варіант A — CLI:**
```bash
npm install -g @anthropic-ai/claude-code
cd say-it-anyway
claude
```

**Варіант B — розширення для VS Code:** пошук «Claude Code» у маркетплейсі.

Що це дає: Claude бачить увесь репозиторій, редагує файли напряму,
запускає тести й лінтер, робить коміти. Ніяких архівів туди-сюди.

**Що покласти в репозиторій одразу:**
- `CLAUDE.md` у корені — правила проєкту (стиль, заборони, контракти)
- `docs/PROVIDERS.md`, `docs/SAFETY.md`, `docs/LICENCES.md` — уже є
- Ці три документи плану

`CLAUDE.md` має містити як мінімум:
- біблійний текст ніколи не генерується моделлю
- максимум 3 корекції
- `improved` не змінює зміст відповіді користувача
- аудіо не зберігається
- у аналітику не потрапляє вільний текст
- кожен уривок має щонайменше два джерела звірки

```
.github/workflows/
  test.yml     на кожен push: lint + unit + Playwright
  deploy.yml   на merge у main: build → scp/rsync → docker compose up -d
```

`POSTGRES_PASSWORD`, `PAYLOAD_SECRET`.

Гілки: `main` → продакшн, `dev` → `staging.sayitanyway.app`.

## 11. Порядок міграції фронта

Не переписувати все одразу. Порядок, за якого в будь-який момент є
працюючий застосунок:

1. Vite + React + TS, порожній каркас
2. Tailwind, токени з `styles.css` у `theme.extend`
3. `packages/content` і `lib` — копіювання без правок
4. Спільні компоненти: `Button`, `Card`, `Layer`, `ThoughtPair`, `Player`
5. Екрани в порядку: Landing → Onboarding → Route → Lesson → Settings
6. Рушій уроку — керований даними, як зараз (`lesson.steps`)
7. PWA: manifest + service worker
8. Playwright: перенести 150 сценаріїв
9. Порівняти зі старою версією екран за екраном

**Приймальний критерій:** усі 150 сценаріїв зелені, вигляд збігається.

## 13. Що перевірити найпершим

**До будь-якої міграції** — запис голосу в Safari на справжньому iPhone.

`MediaRecorder` на iOS історично примхливий, формат там `audio/mp4`, не
webm. Код це враховує, але наживо не перевірявся жодного разу. Якщо там
проблема — вона стосується всієї конструкції продукту, і краще дізнатися
про це зараз, ніж після тижня міграції.

Спосіб перевірки — у `OLEG_SETUP.md`, крок 9.
