## Цільовий стек

```
Фронтенд   React + Vite + Tailwind        (PWA, mobile-first)
Бекенд     Node + Fastify                 API /api/v1
База       PostgreSQL 16                  ЄДИНЕ джерело правди:
                                          контент, профілі, прогрес,
                                          відповіді, фрази, події
CMS        Payload 3 (окремий застосунок) адміністрування контенту
Сервер     Hetzner Cloud, Ubuntu 24.04    Docker + Caddy, шифрований диск
Код        GitHub + GitHub Actions        CI/CD
Аналітика  власна таблиця events + Plausible/GA4
```

**Ідентифікація без реєстрації.** Щоб зберігати прогрес у базі, сервер
має розуміти, чий він. Реєстрація перед першим уроком уб'є воронку саме
там, де ми її вимірюємо, тому — анонімний `deviceId` у підписаному
cookie, виданий сервером на першому візиті. Акаунти додаються пізніше
без втрати накопиченого прогресу; схема це передбачає з першого дня.

> Один ідентифікатор на клієнті лишитися **мусить** — інакше сервер не
> відрізнить двох користувачів. Це один cookie з UUID, не стан
> застосунку. Усе інше живе тільки в Postgres.

### Етап 2 — Сервер

**Робить друг.** Деталі — у `TECH_SPEC.md`, розділ 3.

- [ ] Hetzner Cloud, тип CX22, локація Nuremberg або Helsinki
- [ ] **Ubuntu 24.04 LTS** — див. обґрунтування нижче
- [ ] SSH тільки по ключу, root-логін вимкнено
- [ ] `ufw`: відкриті лише 22, 80, 443
- [ ] `fail2ban` + автоматичні оновлення безпеки
- [ ] Docker + Docker Compose
- [ ] Caddy — HTTPS автоматично, без ручного certbot
- [ ] **Шифрування диска при створенні сервера** — на ньому будуть особисті дані
- [ ] PostgreSQL 16 у Docker, порт **не** назовні
- [ ] Щоденний бекап бази + вивантаження в Hetzner Storage Box
- [ ] Раз на місяць — перевірка відновлення бекапу на порожню базу

**Чому Ubuntu 24.04 LTS:** підтримка до 2029 року, найбільше документації
й відповідей на питання, усі пакети свіжі. Debian стабільніший, але
пакети старіші; Alpine дає економію, якої на цьому масштабі не видно.
Для першого сервера LTS — правильний вибір.

**Результат:** `https://sayitanyway.app` показує заглушку, сертифікат валідний.

### Етап 4 — Міграція фронта на React + Tailwind

- [ ] Vite + React + TypeScript
- [ ] Tailwind із моєю системою токенів у `theme.extend`
- [ ] Порт екранів: `h(...)` → JSX
- [ ] PWA: manifest + service worker

**Що переноситься без правок:** `src/content/*` (уроки, звірені тексти),
`src/lib/safety`, `src/lib/audio`, `src/providers/*`.
**Що замінюється:** `src/lib/storage` — замість `localStorage` клієнт API
(`useProfile`, `useProgress`, `usePhrases`).
**Що переписується:** `src/screens/*` і `src/app/*`.

> Систему токенів із `src/styles.css` треба перенести в `tailwind.config`,
> **а не перемальовувати класами**. Інакше дизайн розповзеться при першій
> же правці.

**Результат:** той самий застосунок, той самий вигляд, інший стек.

**Перевірка:** усі 150 сценаріїв із `scripts/e2e.mjs` проходять на Playwright.

### Етап 5 — База даних і бекенд API

**5a. Схема й міграції**
- [ ] `devices`, `users` (заготовка), `profiles`, `lesson_progress`
- [ ] `answers`, `saved_phrases`, `consents`, `events`, `usage_counters`
- [ ] Міграції через Drizzle або Prisma, тільки вперед
- [ ] `ON DELETE CASCADE` скрізь від `devices` — щоб видалення справді видаляло

**5b. Ідентичність і дані користувача**
- [ ] `POST /devices` — анонімний `deviceId` у підписаному cookie
- [ ] `GET /me`, `PATCH /me/profile`, `POST /me/consents`
- [ ] `DELETE /me` — видаляє все каскадом
- [ ] `GET /me/export` — вивантаження своїх даних (GDPR)
- [ ] Прогрес: `POST /progress/:day/start`, `PATCH`, `POST /complete`
- [ ] Фрази: `POST`, `GET`, `DELETE`

**5c. Мовний цикл**
- [ ] `POST /stt` — аудіо → текст
- [ ] `POST /analyze` — текст → до 3 корекцій + природніша версія
- [ ] `POST /tts` — текст → озвучення
- [ ] `POST /answers` — запис відповіді, **лише за наявності згоди**

**5d. Запобіжники**
- [ ] Rate limiting: 30 сесій на пристрій на добу (`usage_counters`)
- [ ] **Бюджетний стоп**: перевищення денного ліміту → режим демо
- [ ] Аудіо в пам'яті, на диск не пишеться ніколи
- [ ] Кризова відповідь **не зберігається взагалі** й не йде в `/analyze`
- [ ] Нічне видалення відповідей, старших за 90 днів
- [ ] Логи без тексту відповідей
- [ ] OpenAPI-специфікація — для мобільного застосунку

**5e. Черга офлайн**
- [ ] IndexedDB як черга незапісаних змін (не як сховище стану)
- [ ] Синхронізація при старті: спершу відправити чергу, потім читати з сервера

> **Бюджетний стоп — не «на потім».** Без нього один бот за ніч з'їсть
> кількасот доларів на API. Найдорожча помилка, якої легко уникнути.

**Результат:** прогрес живе на сервері. Людина відкриває застосунок на
іншому пристрої з тим самим cookie — і бачить свій маршрут.

## Що НЕ робимо зараз

Щоб не розповзлося:

- ❌ Реєстрація з поштою й паролем — анонімного `deviceId` вистачає;
      таблиця `users` уже є в схемі, вмикається пізніше без міграції даних
- ❌ Оплата й підписки — немає чого продавати, поки не доведено утримання
- ❌ Мобільний застосунок — PWA достатньо; API проєктуємо з думкою про нього
- ❌ Багатомовність — тільки українська
- ❌ Режим «просто хочу англійську» — потребує окремого контенту
- ❌ Дні 8+ і нові маршрути
